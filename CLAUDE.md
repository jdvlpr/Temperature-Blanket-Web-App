# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This file is committed per branch on purpose: branches differ (e.g. `main` has no accounts code; `release/v7` does), so keep it describing what exists on _this_ branch. Workspace-wide notes (sibling iOS app and WordPress plugin, issue tracking) live in the parent folder's CLAUDE.md.

## Overview

[temperature-blanket.com](https://temperature-blanket.com): visualize a location's historical climate data, build a color "gauge" mapping temperature/weather to yarn colors, and preview a crochet/knitting temperature blanket pattern. Projects can be saved locally, shared as a URL, exported to PDF/CSV/PNG/Google Sheets, or published to the public gallery (backed by a headless WordPress site; publishing needs an account). With accounts on, projects, palettes and preferences also sync to the server.

Svelte 5 (runes) + SvelteKit 3 (config lives in `sveltekit({...})` in `vite.config.ts`; there is no `svelte.config.js`; imports use `#lib/...` with file extensions), Skeleton UI 5, Tailwind 4, TypeScript, deployed on Cloudflare Pages via `@sveltejs/adapter-cloudflare`. Package manager is **pnpm**.

## Setup

Copy `.env.example` to `.env`. Location search needs a free GeoNames username (`SECRET_GEONAMES_USERNAME`); weather data needs a free Meteostat/RapidAPI key (`SECRET_METEOSTAT_API_KEY`). Everything else is optional for local dev — POST requests to the WordPress backend are rejected locally without the auth key, which is expected. Signed-out email sign-in also needs `PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA` (Cloudflare's always-pass test site key), which pairs with the test secret in `wrangler.jsonc`.

## Commands

```bash
pnpm install
pnpm dev                 # dev server (vite)
pnpm dev:accounts        # dev server with the accounts UI on; sign-in codes at /api/dev/outbox?to=<email>
pnpm build               # production build — also generates Cloudflare _routes.json
pnpm preview

pnpm check               # svelte-kit sync + svelte-check
pnpm lint                # prettier --check + eslint
pnpm format

pnpm test                # unit + integration + e2e, in that order
pnpm test:unit           # vitest run src — colocated *.test.ts
pnpm test:integration    # boots a dev server, runs vitest against tests/integration (yarn colorway API)
pnpm test:e2e            # playwright, tests/end-to-end, against build+preview over HTTPS on localhost:4173
pnpm test:e2e:cloudflare # builds with accounts on, migrates local D1, runs tests/end-to-end + tests/cloudflare under `wrangler pages dev` (:8788)
pnpm db:migrate:local    # apply migrations/ to the local D1 database
```

`scripts/export-project-palettes.ts --wp <gallery URL> --out <file.json> [--verify]` exports gallery projects' palettes (read-only GraphQL) for the plugin's one-time `wp tempblanket import-palettes`; see its header.

Single unit test file: `pnpm vitest run src/lib/utils/color-utils.test.ts`. Single e2e spec: `pnpm playwright test tests/end-to-end/test-contact.spec.ts`. Playwright's webServer runs `build && preview` itself.

## Architecture

- **`src/lib/state/*.svelte.ts`** — global reactive state (runes), one per concern: `project-state`, `location-state`, `weather-state`, `gauges-state`, `page-state`, `preview-state`. `state/gauges/` holds per-gauge-type state (temperature, rain, snow, daytime, moon-phase). Gauges — weather variable → yarn color ranges — are the core domain concept.
- **Weather days** — a saved project (or gallery page) always opens with its saved days and never searches by itself. `state/weather-days.svelte.ts` keeps, with the project (`weatherDays`), each location's last day got, its early days and newer values kept over; pure logic in `utils/weather-days.ts`. `weather-search.svelte.ts` has three modes: `search` (replaces every day), `new-days` (Weather Data › Only New Days: only days since) and `again` (Search Again: new days added, changed saved days chosen in `modals/SearchAgain.svelte`; kept days get a marker in the table, `modals/KeptDay.svelte`). Publishing gets only new days. Search Again's `weatherChanges` preferences sync.
- **`src/lib/storage/`** — client persistence: projects and palettes in IndexedDB (`idb-keyval`), preferences in Local Storage, `migration-manager.ts` migrates old stored shapes. Update the Local Storage/IndexedDB tables in `README.md` when adding or changing a stored key.
- **`src/lib/features/`** — self-contained features: `pdf/` (built from composable `sections/`), `google-sheets/`, `image-palette/`, `palette-image/`, `charts/`, `diagnostics/`, etc.
- **`src/routes/api/`** — server routes. `location/*` and `weather/v1/meteostat/*` proxy GeoNames/Meteostat to hide keys; `project/+server.ts` used to take anonymous gallery submissions and now answers 410 `SIGN_IN_TO_PUBLISH` (publishing needs an account); Turnstile (`src/lib/server/turnstile.ts`, fails closed; widget `src/lib/components/Turnstile.svelte`) still guards signed-out sign-in codes; `yarn-colorways/{v1,v3}/*` is a public, versioned yarn colorway API (documented at `/api/yarn-colorways`).
- **`src/lib/data/yarns/`** — static yarn/colorway data.
- Routes map roughly 1:1 to top-level nav (`weather`, `yarn`, `yarn-colorway-finder`, `gallery/[id]`, `globe`, `blog/*` dated folders, `my-projects`, `account`, docs pages). `preferences` is reached from the top bar's account button (`account/AccountButton.svelte`: a Popover signed in, a Menu signed out, a plain link in builds without accounts), not the sidebar. The sidebar (`AppNavigation.svelte`: Create · My Library, then Explore · Gallery …) has Create as a Project/Palette menu; My Library (`my-projects` / `my-palettes`) and Gallery (`gallery` / `gallery/palettes`) are single links going back to the side open last (`librarySection` / `gallerySection`). `src/routes/.dev-tools/` is dev-only (redirected away in production by `hooks.server.ts`).
- **Guides & Help** (`/documentation`, the sidebar's "Guides & Help"): `src/lib/docs/docs-index.ts` lists every guide (`/documentation/guides/<slug>`) and reference page (`/documentation/<slug>`) in order, with each one's title, summary and everyday-word `keywords`; the `(docs)` layout takes each page's title, description, breadcrumb and Previous/Next from it, so a page is only its content. Old single-page anchors (`/documentation#weather-sources`) are forwarded by the index via `OLD_ANCHORS`; sections keep those ids. Search is `docs-search.ts`: keywords first, then Pagefind full text (`pnpm build` runs `pagefind` over `.svelte-kit/cloudflare`, indexing only `data-pagefind-body`; `/pagefind/*` is in `routes.exclude`). On this page (`on-this-page.svelte.ts`) collects a guide or reference page's h2/h3; the index has every page beside it instead. Short help (`docs/help-topics.ts`) is shared by the docs pages and `HelpIcon`, which opens it in a dialog, or over an open dialog with Back (`dialog.showHelp`, content kept mounted). `/faq` 301s to the index's Common Questions (`hooks.server.ts`). Reference pages check each fact against the code and reuse its constants and help components; their sections' ids are the old anchors, on the headings, and they end with `RelatedGuides`. Guides (task how-tos) follow one shape: a short intro, What You Need, numbered steps with shots, If Something Goes Wrong, then `RelatedReference`; a guide's video is its index entry's `video` (a YouTube ID), shown by the layout, and nothing shows until one is set. Account parts of any guide or reference page, and links to account-only sections, sit inside `{#if __ACCOUNTS_ENABLED__}`. Shots that need the owner's real data (Ravelry) are HTML comments describing the shot and its alt text. Screenshots are `DocsShot src="<page>/<shot>"`, made light and dark by `node scripts/docs-screenshots.ts --base <preview URL>` (against `PUBLIC_ACCOUNTS_ENABLED=true pnpm build && pnpm preview`, as launched; writes `static/images/docs/` and the sizes in `docs/docs-shots.json`; a new shot needs a stand-in PNG at its path before that build, since prerendering fetches it): re-run it after UI changes. The v7 blog post uses the same shots.
- The Cloudflare adapter's `routes.exclude` (in `vite.config.ts`) controls which paths are static vs. hit a Function — keep API routes out of it; the free plan caps it at ~100 entries, so prefer `/*` wildcards.

### Accounts and sync

Accounts are behind flags and dormant in production until launch:

- `PUBLIC_ACCOUNTS_ENABLED=true` at **build time** includes the account UI (see `app.d.ts`, `vite.config.ts`).
- Server-side, `ACCOUNTS_ENABLED`, `SYNC_ENABLED`, `GALLERY_PUBLISH_ENABLED`, `ACCOUNTS_SIGNUP_LIMIT` and `BETTER_AUTH_SECRET` are Cloudflare bindings/vars. So is `TURNSTILE_SECRET_KEY` (its site key, `PUBLIC_TURNSTILE_SITE_KEY`, is set at build time). `wrangler.jsonc` is **local-only** (no `pages_build_output_dir`); production values live in the Pages dashboard.
- `src/lib/server/cloudflare.ts`: `getPlatform()` returns the bindings (`env`), `ctx.waitUntil` and `caches` from `cloudflare:workers` — adapter-cloudflare 8 no longer sets `event.platform`, so server code calls this instead (undefined while building/prerendering).
- `src/lib/server/platform.ts`: `requireStorage()` returns 503 when the `DB` (D1) / `PROJECTS` (R2) bindings are missing; `/api/dev/*` routes exist only when `ENABLE_DEV_ROUTES=true` and otherwise 404.

Pieces:

- **Auth** — Better Auth (pinned version) in `src/lib/server/auth/`, mounted from `hooks.server.ts` at `/api/auth/*`. Production signs in with Google only: emailed codes (the `emailOTP` plugin, change-email, code fallbacks on the account page) exist only where `EMAIL_SIGN_IN=true`, which `wrangler.jsonc` sets for local dev and e2e (Google can't be driven there); with it off, `GOOGLE_CLIENT_*` is required and no email is sent. `server/email/` sends via Resend, or a dev outbox locally. Client side in `src/lib/accounts/` (`getSignInOptions()` returns `{ google, email }`). Where codes are on, email is kept to a minimum: Google is the main sign-in, a code request needs a Turnstile token unless it's for the signed-in account's own address, codes are limited per IP (`ACCOUNTS_CODE_LIMIT_PER_IP`) and per address, and `EMAIL_DAILY_LIMIT` caps Resend sends a day (every send goes through `sendEmail` in `auth/index.ts`). Better Auth routes that would email but aren't used are listed in `disabledPaths`.
- **Ravelry** — a link-only Better Auth `genericOAuth` provider (`ravelry`), on when `RAVELRY_CLIENT_ID`/`RAVELRY_CLIENT_SECRET` are set (secrets in `.dev.vars`). Never a sign-in method: `handleAuthRequest` refuses `/sign-in/social` for it (1.7.7's genericOAuth registers providers as social ones: link via `/link-social`, callback `/api/auth/callback/ravelry`), won't unlink the last real sign-in method while only Ravelry would remain, and 404s `/get-access-token`, `/refresh-token` and `/account-info` so provider tokens never reach a browser. `src/lib/server/ravelry/` gets tokens via `auth.api.getAccessToken` (refreshing the 24-h token) and calls Ravelry (`api.ts`); routes are under `/api/account/ravelry` (status/disconnect, `projects/[projectId]` read-post-update-unlink + `photos` + `photos/order`, `options`, `yarns`). **Posting needs the project's gallery page, showing its owner's name** (409 `NEEDS_GALLERY_PAGE`/`NEEDS_NAME_SHOWN`): the notes' link line (`project.ts`, brackets encoded) points to `/gallery/<id>`; Anonymous needs unlinking first (409 `RAVELRY_LINKED`) and Unpublish unlinks. Update sends only fields that differ from Ravelry and removes only yarns this app added (`packs` JSON, `ours`); the picture is re-sent only when its `pictureKey` changed. Migrations 0011/0014 keep links, photos, notes and yarns in D1 so gallery pages (only those showing their owner) show photos and notes without the owner's token. Changes made on Ravelry come back only when someone looks (`sync.ts`, from `GET /projects` in `waitUntil`): one `projects/list` call at most every 6 h, then a full read of linked projects whose `updated_at`/photo count/first photo changed (or unread for 3 days); ones missing from the list are unlinked. UI: Account page Connected accounts; the Publish / Edit Gallery Page dialog (`AddToGallery`: Also post to Ravelry, or once posted `RavelryFields`, which edits details, yarns and photos, saved with the same Save after the gallery page) with Ravelry's own mark ("Lumpy", `RavelryMark.svelte`, from ravelry.com/help/logos: unchanged, black or white, with clear space; "On Ravelry, N photos") on a My Library card, View on Ravelry in its ⋮ menu, and an On Ravelry library filter. Photos upload from the browser straight to Ravelry with a one-use token (`photos/upload`; the server finds the image by token, falling back to uploading through the Worker). API docs: `../ravelry-api-documentation.md`.
- **Database** — D1 schema in `migrations/NNNN_*.sql`; add a new numbered file, never edit an applied one. Remote migrations are run by the owner, not by agents.
- **Sync** — `src/lib/sync/engine.ts` is a pure, fetch/IndexedDB-free sync pass (unit-tested against a fake server); `sync.svelte.ts` drives it. Server side: `src/lib/server/sync/` + `src/routes/api/sync/{changes,projects,palettes,preferences,trash}`. Project bodies go to R2, metadata to D1. Rules: optimistic revisions (stale save → 409); never lose data — on conflict the device copy becomes a new "(copy from this device…)" project; an edit beats a deletion; palettes and preferences are last-write-wins per item.
- **Gallery from accounts** — `src/lib/server/gallery/` (`/api/account/gallery`) publishes to WordPress on behalf of a signed-in user; publishing needs an account and never falls back to an anonymous submission. A project or palette has **one gallery page, updated in place** (`PUT /api/account/gallery/[postId]` → gallery plugin 1.9.0's `POST tbgalleryapi/v1/project/<id>` / `palette/<id>`; 501 `UPDATE_UNSUPPORTED` with an older plugin): same link, views and settings; `galleryPost.updatedAt` (migration 0012). Pages from before (several "versions") are tidied in dev with `POST /api/dev/gallery-dedupe`. **A page follows its item into the Trash**: the sync routes hide it (WordPress's trash, `galleryPost.hiddenAt`, migration 0014) when the project or palette is deleted, bring the same page back (plugin 1.10.0's `project/<id>/restore`) when it's restored, and forget it when it's deleted forever (`gallery/visibility.ts`); hidden pages are left out everywhere. So every listed page has a saved item; there are no gallery-only cards. Pages of items deleted before this are hidden in dev with `POST /api/dev/gallery-reconcile`. Publishing a project doesn't share its palettes; palettes are published on their own. Gallery pages show "Published <date>", then "By <name> · 1.2K views" (`GalleryPageHeader`); gallery cards (projects and palettes) say the same in the same order (`GalleryCardByline`), as do My Library's cards, and have a star + ⋮ (`GalleryCardMenu`: Open a Copy, More by <name>, Copy Link; on one's own pages Copy Link and Edit Gallery Page…, via `utils/edit-gallery-page.ts`): views are GraphQL `views` (plugin 1.11.0, all time; `queryGallery` drops the field for an older plugin), names come from D1 through `GET /api/gallery/owners?ids=` (`lib/state/gallery-owners.svelte.ts`, one request per page of cards), only for pages showing their owner.
- **Stars** — private bookmarks of other people's gallery pages (migration 0015 `galleryStar`, `src/lib/server/gallery/stars.ts`, `/api/account/gallery/stars`): sign in to star, at most 500, never views or Popular, never on one's own pages (GET returns the account's own post IDs too, so their cards show no star). `lib/accounts/gallery-stars.svelte.ts` loads them only when a star (`GalleryStarButton`, on gallery cards and in `GalleryPageHeader`) or My Library shows. My Library's Mine | Starred switch (`LibraryScope`, `?show=starred`, `state/library-scope.ts`) shows Starred as the page's list (`StarredGalleryPages`: the gallery's cards, read by ID from GraphQL), with the same toolbar and its own sorts (Recently starred, Newest published, Most viewed). Pages WordPress doesn't return are hidden, not unstarred.
- **Sharing model** — nouns and verbs users see: **Link** (Copy Link: a copy anyone can open; theirs never changes), **Gallery Page** (Publish, then Edit: update, Anonymous, Unpublish), **Your Gallery** (`/gallery/by/<id>`, "Ada’s Gallery": the pages showing the owner's name), and for projects **Ravelry** (Post / Update / Unlink, inside Edit). There is no Share dialog: one builder (`accounts/share-rows.ts`, `shareRows`) makes the share rows, Copy Link then the gallery page by state (Sign In to Publish; Publish to Gallery…, or disabled with why; once published View Gallery Page, Edit Gallery Page… with "Changed since publishing", Unpublish… via `modals/UnpublishDialog.svelte`) then View on Ravelry, and they sit right where they're opened: a My Library card's flat ⋮ (`MoreMenu`, whose items take `detail` and `disabled`), the planner's Project menu and the Yarn page's Palette menu (`ShareRows.svelte` panel rows in their Share group; both menus share one shape of `PanelGroup`s — card, Download (+ Start a Project with It), Share, Palettes (planner), Project/Palette (New, Open…, Duplicate, Move to Trash), help — and open New and what Open chooses in place, the planner asking first via `utils/leave-project.ts` (`modals/SaveFirst.svelte` when `unsavedWork()` or never saved). Open (`modals/OpenProject.svelte`, `routes/yarn/OpenPalette.svelte`, both in `modals/OpenShell.svelte`; also ⌘/Ctrl+O) lists saved items with a search and, signed in, Mine | Starred, a starred page opening as a copy (`utils/open-copy.ts`, shared with `GalleryCardMenu`); `routes/yarn/PaletteMenu.svelte` saves an unsaved palette before publishing), and the preview's Share button, a menu (`buttons/SendToGalleryButton.svelte`, `utils/project-share.ts`). My Library cards say "Published <date>" (the Ravelry mark beside it), then views and a warning ⟳ when changed since (the out-of-sync icon's color; the menus' "Changed since publishing" too), or "Saved <date>" (`LibraryInfoLine`; own pages' views from `accounts/own-page-views.svelte.ts`). Palettes reach the planner through Get Colors (My Palettes, Palette Gallery, Gradients: `modals/PaletteSource.svelte`) and leave it through the Project menu's Palettes group (a row per gauge: Save to My Palettes, then its exports; `modals/GaugePaletteExport.svelte`); the Yarn page's Start a Project with It opens `/?palette=<yarn link>` (`state/starting-palette.ts`). `AddToGallery` (projects) / `SharePalette` (palettes) are the Publish / Edit Gallery Page dialogs (Save; Unpublish asks first, `account/UnpublishConfirm.svelte`); a gallery page's owner opens the same dialog from the page (`account/GalleryPageEdit.svelte`, or `modals/GalleryPageManage.svelte` when the item isn't on this device yet).

Server unit tests that need a database use `src/lib/server/test-d1.ts`, an in-memory D1 stand-in on `node:sqlite` with the migrations applied.

## Icons and fields

- Icons are sized by CSS tokens in `src/css/main.css`: `--icon-size` (1.25rem) for every icon, `--icon-size-sm` (1rem) via the `icon-sm` class for dropdown/row chevrons, external-link and other icons inline with text. Never use Lucide's `size` prop (CSS overrides it); use `icon-sm`, or a `size-*` class only for deliberately large icons (empty states, spinners). Icons in `btn-sm` are small automatically; Buttons, icon buttons and fields share one height, twice their text size plus `--spacing(1.5)` (40px at normal settings; `src/css/main.css`); `btn-icon` is that size as a circle, with an invisible tap area of at least 44px (its `::after`).
- Joined fields use `FIELD_GROUP`; an icon at the start of a select uses `FIELD_ICON` with `pl-11` on the select (`src/lib/constants/class-constants.ts`). Don't add `text-*` to `.input` (it changes its height); use Skeleton's `field-*` sizes.

## Testing conventions

- Unit tests are colocated next to the code as `*.test.ts`.
- `tests/integration/` hits real dev-server routes (yarn colorway API).
- Under `tests/cloudflare/`, give pages a test IP with `useTestIp()` (helpers.ts), never `setExtraHTTPHeaders`: Cloudflare refuses a `CF-Connecting-IP` header sent to its own sites, such as Turnstile's.
- `tests/end-to-end/test-*.spec.ts` run against the preview build; `tests/cloudflare/` covers accounts, sync and gallery routes and only runs under `pnpm test:e2e:cloudflare`.
- Optional HTTPS dev via a Tailscale cert/key (`PRIVATE_TAILSCALE_CRT_PATH`/`PRIVATE_TAILSCALE_KEY_PATH` in `.env`) for testing on other tailnet devices.
